Production Till STK, mapped clearly.

This guide documents the exact product, identifiers, API calls, callbacks, and status outcomes used by XCASPER SPACE STK TILL PUSH.

01

Choose the right Daraja product

This app uses M-Pesa Express / Lipa na M-Pesa Online for a customer-facing STK prompt. It is not the Business Buy Goods B2B API. In your production Daraja app, add the M-Pesa Express/Lipa na M-Pesa Online product and use its production passkey.

Important: Business Buy Goods is a separate business-to-business use case. It does not replace the STK Push product.
02

Map the Till identifiers

For a Buy Goods Till STK request, use the H.O./Store number as BusinessShortCode and the actual Till number as PartyB.

03

Correct API calls

POST https://api.safaricom.co.ke/oauth/v1/generate?grant_type=client_credentials
Authorization: Basic base64(CONSUMER_KEY:CONSUMER_SECRET)

POST https://api.safaricom.co.ke/mpesa/stkpush/v1/processrequest
Authorization: Bearer ACCESS_TOKEN

Sandbox swaps api.safaricom.co.ke for sandbox.safaricom.co.ke.

05

Production callback checklist

  • Use a public, internet-accessible URL.
  • Use HTTPS in production; HTTP is only allowed for sandbox simulation.
  • Register the exact confirmation/callback URL in Daraja before testing.
  • Do not use public URL testers or blocked keywords in the URL.
  • Return {"ResultCode":0,"ResultDesc":"Accepted"} quickly, then process the result.
In this app: the callback is /api/callback; the UI polls the server and shows successful, cancelled, insufficient-balance, timeout, or failed states.
06

What each result means

Successful — Safaricom returned ResultCode 0.

Cancelled — the customer cancelled the prompt.

Insufficient balance — the customer balance could not cover the amount.

No response — the prompt expired or the customer did not act.
